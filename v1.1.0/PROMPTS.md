## 공통 전제 (v1.1.0)

- 기준 문서는 `PRD_v.1.1.0.md`와 `../v1.0.0/PRD.md`, 프로젝트 규칙은 저장소 루트의 `CLAUDE.md`.
- **v1.0.0 보존:** `v1.0.0/` 폴더, 태그 `v1.0.0`, 브랜치 `backup/v1.0.0`은 절대 수정·삭제하지 않는다. 작업은 `main` 브랜치의 `v1.1.0/` 폴더에서 하고, 커밋·push·태그는 내가 요청할 때만 한다.
- **고정 모드 회귀 금지:** 고정 모드는 v1.0.0과 똑같이 동작해야 한다. 단계마다 `node tests/run-all.mjs`와 v1.0.0 AC-1~AC-10을 다시 확인한다.
- **적용 전 검사 원칙 유지:** 로봇 이동은 물리엔진보다 먼저 기존 안전 게이트(`motion.js` → `safety.js`)를 통과해야 한다. 물리엔진은 로봇 이동 결과에 대한 물체 반응만 계산한다.
- **의존성:** Three.js + Rapier(`@dimforge/rapier3d-compat`) 두 개만, CDN 버전 고정. 빌드 도구 없이 ES 모듈로 작성한다.
- **언어:** UI 문구·주석은 한국어, 전문 용어는 영문 병기. 순수 계산 모듈은 DOM에 의존하지 않게 해서 Node 테스트와 Worker에서 재사용한다.
- **변경 기록:** 변경 내용은 `CHANGELOG.md`의 `[Unreleased]`에 기록한다.

## [v1.1.0] 1-A단계 — Rapier 연동 · 시뮬레이션 모드 · 동적 물체

```
PRD_v.1.1.0.md와 현재 코드를 읽고, FR-17·FR-18·FR-20과 2장(시뮬레이션 모드), 6.4(저장 스키마 v2)를 구현해줘.

[범위]
1. Rapier 연동 (js/physics.js)
   - @dimforge/rapier3d-compat 최신 안정 버전을 확인해 CDN 주소를 버전 고정으로 쓰고, 그 버전을 README와 PRD_v.1.1.0.md에 기록.
   - 물리 월드: 로봇 좌표계(Z-up, mm) ↔ Rapier(SI, m·kg·s) 변환을 한 곳에서 처리.
   - 중력 −Z 9.81 m/s², 바닥(Z=0) 정적 충돌체.
   - 물리 스텝은 기존 고정 60 Hz tick 안에서 실행 (로봇 이동 → 물리 스텝 → 렌더).
   - WASM 로딩은 비동기로 하고, 실패하면 고정 모드만 사용 가능 + 원인 안내 (앱은 계속 동작).
2. 동적 물체 (FR-18)
   - 박스·구·원기둥을 기존 장애물 정의(type/size/pos/rot)로 동적 바디 생성.
   - 물체별 물성: 밀도(질량 자동) 또는 질량, 마찰, 반발 — 장애물 편집기에 입력 추가 (물리 모드에서만 사용).
   - 매 프레임 물리 결과로 3D 메쉬 갱신. 범위 이탈(Z < −1 m 등) 물체는 비활성화 + 목록에 표시.
3. 시뮬레이션 모드 (규칙 0, FR-20)
   - 장애물 패널 상단에 "시뮬레이션 모드: 고정 / 물리" 스위치. 물체별 고정/물리 선택은 만들지 않는다.
   - 배치(Layout, 저장됨)와 시뮬레이션 상태(저장 안 됨) 분리:
     고정→물리 = 배치에서 시작 / 물리→고정 = 배치로 복원 / "현재 상태를 배치로 저장" / 리셋 버튼.
   - 물리 모드 컨트롤: 실행/일시정지, 리셋, 현재 상태를 배치로 저장.
   - 모드 전환·리셋은 로봇 정지 중에만 허용 (실행 중이면 안내 후 거부).
   - 물리 모드로 전환할 때 안전 감지 토글은 바꾸지 않고, 장애물 충돌 감지가 켜져 있으면 PRD의 안내 문구를 세션당 1회 표시.
   - 상단 바·상태바에 현재 모드와 물리 계산 시간(ms/step) 표시.
4. 저장 스키마 v2 (state.js)
   - settings.simMode, settings.gravity, obstacles[].physics, cell(빈 값) 추가.
   - v1 → v2 마이그레이션 (simMode=static, 기본 물성). 내보낸 v1.0.0 JSON 가져오기도 같은 경로로 변환.
   - localStorage 키는 robosim-lite:v1 유지, 형식은 schemaVersion으로 구분.
5. tests/physics.mjs (Node에서 Rapier 실행)
   - 공중 박스 낙하 → 바닥 안착 높이, 박스 3개 적층 안정, 같은 입력 두 번 실행 시 같은 결과(결정성), 마이그레이션 v1→v2.
   - tests/run-all.mjs에 포함.

[제약]
- 고정 모드에서는 물리엔진을 스텝하지 않고, 기존 동작·성능(안전 검사 시간 포함)이 v1.0.0과 같아야 한다.
- 물리엔진 로딩이 첫 화면 표시를 막지 않는다 (고정 모드 화면 먼저).

[완료 기준 — 직접 확인하고 결과 보고]
- AC-12: 공중에 배치한 박스·구·원기둥이 물리 모드에서 떨어져 바닥/다른 물체 위에 멈추고, 고정 모드로 돌아가면 배치로 복원
- AC-13: 물체별 모드 선택이 없고, 로봇 이동 중 모드 전환이 거부됨
- AC-20: v1.0.0 저장 데이터와 내보낸 JSON이 고정 모드 같은 장면으로 열림
- 물체 50개 물리 모드에서 FPS와 ms/step 측정값 보고
- node tests/run-all.mjs 통과(physics 포함), v1.0.0 AC-1~AC-10 회귀 없음, 콘솔 에러 0건
```

## [v1.1.0] 1-B단계 — 로봇 운동학 바디 · 물리 모드 안전 감지 · 성능

```
PRD_v.1.1.0.md와 현재 코드를 읽고, FR-19, 4.3(물리 모드 안전 감지 규칙), 4.4, NFR-9·NFR-10을 구현해줘.

[범위]
1. 로봇의 물리 표현 (FR-19)
   - 로봇 링크를 기존 충돌 모델과 같은 캡슐로 Rapier 운동학 바디(kinematic position-based)로 등록.
   - 매 tick 안전 검사를 통과해 적용된 자세로 링크 바디의 다음 위치를 설정 → 로봇이 물체를 밀어냄, 로봇은 밀리지 않음.
   - 로봇 링크와 작은 물체에 CCD 적용 (빠른 이동 시 관통 방지).
   - 로봇 모델을 바꾸면 링크 바디를 다시 만든다.
2. 물리 모드 안전 감지 (PRD 4.3 표 그대로)
   - 장애물 충돌 감지 ON: 로봇 링크가 물체에 닿기 전에 정지·알람 (적용 전 검사, 그 tick의 물체 위치 기준).
   - OFF: 정지하지 않고 물체를 밀어냄.
   - 움직이는 물체가 정지한 로봇에 부딪히면(감지 ON) 알람 + 로그에 "외부 물체 충돌".
   - 성능: 물체 컴파일 결과를 재사용하고 위치·회전만 매 tick 갱신.
3. 자동 경로 계획 (4.4)
   - 물리 모드에서 계획 요청 시 그 순간 물체 위치 스냅샷을 정적 장애물로 Worker에 전달.
   - 계획 이후 물체가 20 mm 이상 움직이면 "다시 생성 권장" 표시.
4. 성능·결정성
   - 물리 스텝 + 안전 검사 합계 프레임당 4 ms 이내 (동적 물체 50개). 부족하면 원인을 찾아 최적화.
   - 같은 배치·같은 명령 → 같은 결과 (tests/physics.mjs에 로봇이 박스를 미는 시나리오 결정성 테스트 추가).

[완료 기준 — 직접 확인하고 결과 보고]
- AC-14: 물리 모드에서 감지 OFF면 로봇이 박스를 밀어내고, ON이면 닿기 전에 정지·알람 (전환 시 토글 유지 + 안내)
- AC-19: 동적 물체 50개에서 60 FPS, 같은 시나리오 2회 실행 시 물체 최종 위치 일치 (수치 보고)
- 물리 모드에서 자동 경로 계획 → 실행 시 충돌 없음, 계획 후 물체를 옮기면 stale 경고
- node tests/run-all.mjs 통과, v1.0.0 AC-1~AC-10 회귀 없음, 콘솔 에러 0건
```

## [v1.1.0] 2-A단계 — 그리퍼 · TCP · 파지/놓기

```
PRD_v.1.1.0.md와 현재 코드를 읽고, FR-21·FR-22를 구현해줘.

[범위]
1. 그리퍼 (js/gripper.js, js/gripper-panel.js)
   - 평행 2지 그리퍼 근사 형상(몸체 + 손가락 2개), 설정에서 켜기/끄기(기본 끔).
   - 기본 치수는 로봇 sizeClass별 3종(PRD FR-21 표: 길이, 최대 벌림 폭, 손가락, 몸체, 개폐 시간, 최대 파지 질량).
   - 사용자 수정값은 로봇 모델별로 저장(settings.gripper.overrides[robotId]), "기본값으로 되돌리기", 입력 범위 검증.
   - 열기/닫기 버튼, 상태 표시(열림/닫힘/파지 중: 물체명), 개폐 애니메이션(개폐 시간).
2. TCP 오프셋
   - 그리퍼를 켜면 TCP = 손가락 끝 중심. TCP 표시, 직교 조그, IK, 경로 계획 TCP 목표, 경유점 표시가 모두 새 TCP 기준.
   - 그리퍼를 켜고 끌 때 저장된 Waypoint(관절값)는 그대로 두고, TCP 표시만 바뀐다는 점을 안내.
3. 충돌 모델
   - 그리퍼 몸체·손가락을 로봇 충돌 모델에 추가 (자기 충돌: 그리퍼–전완·상완 쌍).
   - 장애물 충돌: 손가락은 PRD 4.3 규칙대로 검사에서 제외, 몸체는 링크와 같은 규칙.
   - 경로 계획 Worker에도 그리퍼 형상을 전달.
4. 파지/놓기 (FR-22, 물리 모드에서만)
   - 닫기: 손가락 사이에 있고 폭 ≤ 최대 벌림 폭이며 질량 ≤ 최대 파지 질량인 물체를 그리퍼에 고정 연결 (손가락은 물체 폭에서 정지).
   - 실패 안내: 빈 손 닫힘 / 질량 초과(x kg > y kg). 고정 모드에서는 개폐만 하고 "물리 모드에서 파지할 수 있습니다" 안내.
   - 열기: 연결 해제, 그리퍼 속도를 물체에 전달, 동적 바디로 복귀.
   - 파지한 물체는 로봇의 일부로 취급 (다른 물체와 닿으면 감지 ON일 때 정지·알람).
5. tests/physics.mjs에 파지→들어올리기→이동→놓기 후 안착 위치, 질량 초과 거부 테스트 추가.

[완료 기준 — 직접 확인하고 결과 보고]
- AC-15: 소·중·대형 모델에서 각각 크기에 맞는 기본 그리퍼가 장착되고, TCP·직교 조그·IK가 새 TCP 기준. 치수 수정이 그 로봇에만 저장되고 새로고침 후 유지
- AC-16: 물리 모드에서 박스 위로 내려 닫으면 함께 움직이고, 열면 그 자리에 안착
- 그리퍼를 켠 상태에서 고정 모드 AC-3~AC-7 동작 확인 (그리퍼 포함 충돌 감지·경로 계획)
- node tests/run-all.mjs 통과, 콘솔 에러 0건
```

## [v1.1.0] 2-B단계 — Waypoint 동작 · Pick & Place 자동 생성

```
PRD_v.1.1.0.md와 현재 코드를 읽고, FR-23·FR-24를 구현해줘.

[범위]
1. Waypoint 도착 동작 (FR-23)
   - Waypoint에 action: 없음 / 그리퍼 열기 / 그리퍼 닫기 / 대기(초). 목록에 아이콘 표시, 편집 UI.
   - 시퀀스 재생 시 도착 → 동작 실행 → 완료 후 다음 Waypoint. 일시정지·정지·알람 시 동작도 중단.
   - 저장 스키마 waypoints[].action, 마이그레이션 기본값 none.
2. Pick & Place 작업 (FR-24, js/task.js)
   - 자동 경로 계획 패널에 작업 유형: "이동 (A → B)" / "Pick & Place".
   - 입력: 집을 물체(목록 선택), 놓을 위치(TCP 좌표 또는 Waypoint), 파지 방향(위에서 수직 / 현재 방향 유지), 접근 높이(기본 100 mm).
   - 구간 자동 생성: ① 현재→파지 접근점(자동 경로) ② 직선 하강 ③ 닫기 ④ 직선 상승
     ⑤ 놓기 접근점까지(자동 경로, 파지 물체를 로봇 형상에 포함) ⑥ 직선 하강 ⑦ 열기 ⑧ 직선 상승.
   - 계획 시 물체 위치는 그 순간 스냅샷, 집을 물체는 ①~④ 장애물에서 제외.
   - 각 구간 실패 시 구간명 + 원인 표시 (예: "놓기 접근점: 도달 불가(Out of Reach)").
   - 결과 표시: 경유점 라벨 + 파지·놓기 아이콘, "경유점을 Waypoint 목록에 추가" 시 그리퍼 동작도 함께 저장.
   - 실행: 파지 직전 물체 위치 재확인, 10 mm 이상 벗어나면 정지 + "물체 위치 변경 — 다시 계획 필요".
