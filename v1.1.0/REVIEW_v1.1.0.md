정상 확인된 핵심 동작:
- **좌표·단위·회전 일치:** 배치 회전(ZYX) → 충돌 검사 회전행렬 → 물리 쿼터니언 → Three.js 렌더 쿼터니언이 2,000개 무작위 자세에서 최대 5.6e-16 차이로 일치. "현재 상태를 배치로 저장" 왕복 오차 6.5e-15. 누운 원기둥이 물리 안착 후 z = 39.9 mm(기대 40), 축이 수평.
- **안전 게이트:** 물리 모드·그리퍼·파지 물체 모두 이동 **전에** 검사한다. 감지 ON이면 물체에 닿기 전 정지(전완 ↔ 박스, 박스 이동 0 mm), OFF면 밀어냄(619 mm). 손가락 개폐도 매 스텝 검사해 "그리퍼 동작 중 충돌"로 정지. 파지 물체가 바닥에 닿기 전 "파지한 물체 ↔ 바닥"으로 정지.
- **그리퍼 형상을 반영한 경로 계획:** 그리퍼를 모르는 계획은 손가락이 벽에 −11.5 mm 침범, 반영한 계획은 실행 궤적 전 구간 위반 0(최소 59 mm). 파지 물체도 같은 결과(−22.8 mm → 위반 0, 최소 103 mm). `tests/gripper.mjs`에 상시 항목으로 있음.
- **Pick & Place:** 소·중·대형(IRB 1200 / KR 20 / R-2000iC) 벽 너머 운반, 실행 중 위반 0, 놓은 위치 오차 0.5~3.9 mm. 계획 후 물체가 30 mm 움직이면 파지 직전에 "물체 위치 변경 — 다시 계획 필요"로 정지.
- **새 월드 결정성:** 같은 배치로 새 물리 월드를 두 번 만들면 600 스텝 후 결과가 비트 단위로 같고, Pick & Place 실행 재현도 2회 동일(Node).
- **성능:** 물체 50개 낙하 중 60.3 FPS, 최대 프레임 간격 17 ms, 상태바 2.4 ms/step. Node: 물체 50개 + 그리퍼 + 파지 물체로 evaluatePose 26 µs, 물리 스텝 중앙값 0.12 ms(95% 0.35 ms).
- **실패 대응:** CDN을 막으면 "물리엔진을 불러오지 못해 고정 모드로 동작합니다 … 인터넷 연결을 확인하세요" 안내 후 고정 모드로 정상 조작. 모드 전환 15회 반복 후 JS 힙 22.7 → 22.6 MB(누수 없음), 60 FPS.
- **하위 호환:** v1.0.0 형식(schemaVersion 1) JSON 가져오기 → schema 2, 고정 모드, 로봇·관절·물체·테마 동일, 물체 기본 물성, Waypoint 동작 none, 그리퍼 꺼짐.

### 4.3 집중 점검 항목별 결론

- **단위·좌표계·회전 규약:** 일치(1장 정상 확인 참고). mm ↔ m 변환은 `physics.js` 경계에서만 일어난다(`MM = 0.001`). 렌더는 물리 쿼터니언을 그대로 쓰고, 안전 검사는 같은 쿼터니언에서 만든 회전행렬을 쓴다(`main.js:1506` applyPosesToSafety).
- **적용 전 검사 원칙:** 지켜진다. 로봇 이동은 `MotionController.tick → sweepCheck`를 통과한 자세만 물리 바디에 전달된다(`main.js:1732`). 그리퍼 개폐는 매 스텝 재평가해 새 위반·악화면 멈춘다(`main.js:1264`). 파지 물체는 링크 9로 검사에 포함된다. **알람 중 우회 경로**: 로봇 이동·조그·재생·계획 실행은 모두 거부된다. 예외는 그리퍼 개폐(알람 중에는 멈추지만 Reset 후 재개, M-4)와 단계 실행의 대기 구간(M-2)이다.
- **배치/상태 분리:** 모드 전환·리셋·새로고침·가져오기에서 배치가 손실되지 않는다. 물리 모드 저장 상태를 새로고침하면 배치에서 다시 시작한다(3단계에서 복원 직후 오알람도 수정됨). 혼동 지점은 물리 모드 중 편집(m-3)과 파지 중 배치 저장(m-7)이다.
- **파지 판정·놓기·예외 상황:** 폭·위치 경계는 E5 실험대로 동작(손가락 끝보다 물체 중심이 20 mm 아래까지 허용). 놓은 뒤 안착 안정(z 오차 0.1 mm 이하). 파지 중 로봇 변경·그리퍼 끄기 → 놓기(물체 낙하), 모드 전환·리셋 → 파지 해제 후 배치 복원, 알람 → 로봇은 정지하고 물체는 계속 붙어 있음(정상).
- **Pick & Place 구간 연결:** 각 구간은 앞 구간의 마지막 관절값에서 시작해 관절이 연속이다(`task.js`). TCP 오프셋은 계획(플랜지 변환)·직선 구간·실행·표시·Waypoint 저장에서 같은 `toolMatrix`를 쓴다. 계획 스냅샷과 실행 불일치는 파지 직전 위치 재확인(10 mm)으로 처리한다. 놓을 자리에 다른 물체가 들어온 경우는 실행 중 안전 검사가 막는다(놓기 위치 재확인은 없음).
- **결정성·성능·로딩 실패·메모리:** 결정성은 M-1, m-6. 성능은 NFR-9 충족. 로딩 실패는 대응되나 재시도 불가(m-4). 메모리는 JS 힙 기준 누수 없음.
- **저장 스키마 v2:** 마이그레이션 1 → 2(simMode static), sanitize에서 그리퍼·물성·Waypoint 동작 기본값과 범위 검증. 알 수 없는 로봇 id의 그리퍼 수정값은 버림. v1.0.0 JSON 가져오기 정상(AC-20).
