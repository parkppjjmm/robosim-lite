## 1. 목표 / 비목표

**목표**
1. 대형 로봇과 측면 로봇(L·R)의 **J1~J6 각도·속도·전류(+ 토크)** 를 버튼으로 켜고 끄는 실시간 표시.
2. 운영 중 데이터를 **시간대별(시뮬레이션 시간)·상황별(동작·단계·사이클·부하·알람)** 로 기록하고 **엑셀(.xlsx)** 로 추출.
3. 이 데이터로 **의미 있는 머신러닝**을 하기 위한 과정·과제·다음 기능을 정의(5장).

**비목표 (이번 버전)**
- 실제 로봇 전류 측정: 시뮬레이터에는 모터·감속기 모델이 없다. 전류·토크는 **근사 동역학으로 추정**한다(3장). 실측과 바로 비교할 수 없다(5.6 sim-to-real 참고).
- 머신러닝 모델 학습·배포 자체: 이번에는 데이터 기반과 계획까지만 한다. 학습은 다음 단계(5.4, 7장).

## 2. 기능 요구사항

### FR-37 실시간 표시 (버튼 토글)
- 오른쪽 패널 **실시간 계측 · 데이터 (Telemetry)** 섹션에 토글 버튼 4개: **각도(Angle)**, **속도(Velocity)**, **전류(Current)**, **토크(Torque)**.
- 켠 항목만 3D 화면 왼쪽 위 **오버레이 표**(J1~J6 × 선택 항목)에 약 10 Hz로 갱신한다. **하나도 켜지 않으면 표가 보이지 않는다.**
- **표시할 로봇** 선택: 대형 · 왼쪽 측면 · 오른쪽 측면(설치된 로봇만).
- 모든 항목에 막대가 붙고, '그래프' 버튼으로 시계열 그래프를 켠다(FR-41).
- 전류 칸에는 정격 대비 막대가 붙는다. 70% 초과면 주황, 90% 초과면 빨강이다. 표 아래에 "정격 N A 기준 막대 · 추정값"을 표시한다.
- 단위: 각도 deg, 속도 deg/s, 전류 A, 토크 N·m.

### FR-38 관절 계측 모델 (`js/telemetry.js` `JointTelemetry`)
- **각도:** 시뮬레이터 관절값 그대로(적용 전 안전 검사를 통과해 실제 적용된 값).
- **속도:** 60 Hz 스텝의 정확한 차분 `(q_k − q_{k−1}) / Δt`.
- **가속도:** 평활한 속도(지수 평활 0.4)를 미분한 뒤 다시 평활(0.3)하고, 상한 ±600 deg/s²를 둔다.
  - 시뮬레이션 궤적은 구간이 바뀔 때 속도가 순간적으로 바뀐다(실제 제어기는 가감속으로 완화). 그래서 미분 가속도가 최대 1,900 deg/s²까지 튀어, 이를 억제한다.
- **토크(근사 동역학):** `τ_i = 중력 + 관성 + 마찰 + 외력`
  - **중력:** 링크 캡슐 질량(유효 밀도 1,400 kg/m³ × 캡슐 부피, 중심 = 캡슐 중점) + 툴 질량 + 부하가 축 i에 만드는 토크. 위치 에너지 미분(dV/dq)과 일치함을 전 모델에서 검증(상대 오차 < 1e-3).
  - **관성:** `I_eff,i · α_i`. I_eff = 축 i 뒤 질량들의 (축까지 거리²) 합.
  - **마찰:** 정격토크 × (쿨롱 0.04 · tanh(ω/0.02) + 점성 0.03 · ω[rad/s]).
  - **외력:** 툴이 욕면 아래에 잠긴 채 움직이면 점성 저항 `F = −450 N·s/m × 잠김 × v_TCP`을 `Jᵀ·F`로 더한다.
- **부하:** 툴 질량(대형 스키머 9 kg, 소형 스키머 2 kg, 밀대 1.5 kg, 그리퍼 = 가반 20%) + 파지 물체 질량 + 스쿱 위 드로스 질량. 스쿱이 욕면 밖에 있을 때만 더한다(잠겨 있으면 부력이 받친다).
- **전류:** `I_i = 정격전류 × τ_i / 정격토크_i + 잡음`
  - 정격전류: 소형 4 A, 중형 10 A, 대형 25 A.
  - 정격토크_i: 대표 자세 5개의 정적 토크 최대 × 1.5 + I_eff,max × 6 rad/s².
  - 잡음: 정격의 0.5%(표준편차), 시드 고정 → 재현 가능.

### FR-39 데이터 기록 (`TelemetryLog`)
- **● 기록 시작 / ■ 기록 정지.** 샘플링 10·20(기본)·30·60 Hz.
- 샘플 시각마다 **로봇마다 1행**: 대형 + 설치된 측면 로봇.
- 시간 기준은 **시뮬레이션 시간**(60 Hz 스텝 누적, 기록 시작 = 0)이다. 실제 시각(ISO)도 함께 남긴다.
- **상황 라벨**
  - 동작(activity): idle · jog · cartesian · waypoint · plan · planning · skim · push · hold · wait · alarm
  - 단계(phase): 레인 접근 · 스쿱 하강 · 스윕 · 스쿱 상승 · 뒤로 기울임 · 박스로 이동 · 기울여 쏟기 · 밀기 …
  - 사이클 번호, 레인 번호, 알람 여부
- **사이클 요약:** 사이클이 끝나면 1행 — 시간, 회수 개수, 축별 피크·RMS 전류, 에너지(Σ|τ·ω|·Δt), 최대 부하, 결과(done·alarm·in-progress).
- **이벤트:** 기록 시작·정지, 단계 변화, 알람·해제.
- 한도 30만 행(엑셀 한도 104만 행 안). 넘으면 기록을 멈추고 안내한다.

### FR-40 엑셀 추출
- **⬇ 엑셀 추출 (.xlsx)** → `robosim-telemetry-YYYYMMDD-HHMMSS.xlsx` 다운로드. 외부 라이브러리 없이 자체 작성기(`js/xlsx.js`: Office Open XML + ZIP 무압축 + CRC-32)로 만든다.
- **시트 5개**

| 시트 | 내용 |
|---|---|
| `data` | 시간대별 로봇별 행 (49열, 4장) |
| `cycles` | 사이클 요약 (24열) |
| `events` | 단계 변화·알람·기록 시작/정지 |
| `columns` | 열 설명·단위 (한국어) |
| `meta` | 앱 버전, 샘플링, 셀 설정(드로스 수·시드·발생률…), 측면 로봇 구성, 임계값, 로봇별 추정 질량·정격전류·정격토크, 전류 모델 가정 |

- 첫 행은 굵게 표시하고 고정한다. 열 이름은 **ASCII**다(pandas `read_excel`로 바로 사용).

### FR-41 그래프·막대 시각화 (2026-11-05 추가 요청: "각도·속도·토크도 전류처럼 시각화, 그래프")
- **오버레이 막대**
  - 각도: 관절 범위 안의 위치 표시(세로선 = 0°, 끝 5% 안이면 주황)
  - 속도: 최대 속도 대비
  - 전류·토크: 정격 대비
  - 크기 막대는 70%를 넘으면 주황, 90%를 넘으면 빨강
- **시계열 그래프:** '📈 그래프' 버튼을 켜면 3D 화면 아래쪽에 켠 항목(각도·속도·전류·토크)마다 한 칸씩 J1~J6 선(색 구분, 범례)을 그린다.
  - 구간은 최근 5·10·30 s(시뮬레이션 시간) 중에서 고른다.
  - 세로축은 자동 범위다. 각도는 최소~최대, 나머지는 0 기준 대칭 + 0 점선.
  - 그래프용 이력은 기록 여부와 관계없이 20 Hz로 최근 30 s를 로봇마다 보관한다.
  - canvas로 직접 그리고(라이브러리 없음), 다크/라이트 테마를 따른다.
- 손목 축(J4~J6) 정격토크 하한: 가반하중 + 툴이 툴 끝에서 수평으로 걸린 토크 × 1.5 + 관성. 대표 자세에서는 툴이 축과 나란해 정격이 작게 잡혀, 덤프 자세에서 추정 전류가 정격의 3배 이상으로 튀던 문제를 고쳤다.

### 측정 메모 — 물리 스텝 시간 (CCD 아님)
- 작업 중 브라우저 상태바에 `PHYS ~100 ms/step`이 보일 때가 있었다. CCD(연속 충돌 검사) 설정을 바꿔 가며 쟀지만 같은 설정에서도 결과가 들쭉날쭉했다.
- Node에서 같은 작업량으로 비교하면 CCD를 켜든 끄든 같았다: 60 s 물리 합계 약 2.5 s, 최대 9~13 ms, 20 ms 초과 0회.
- 따라서 같은 PC에서 앱을 함께 실행해 CPU를 나눠 쓴 측정 잡음으로 판단한다. CCD 설정은 v1.1.1과 같게 유지한다(변경 없음).

## 5. 머신러닝으로 의미 있는 결과를 만드는 과정 (제안)

### 5.1 무엇을 맞힐 것인가 — 과제 후보

| # | 과제 | 입력 → 출력 | 왜 의미 있나 | 지금 데이터로 가능? | 난이도 |
|---|---|---|---|---|---|
| A | **드로스 부하 가상 센서** | 전류·각도·속도·가속도 → 스쿱 위 드로스 kg | 카메라·저울 없이 "이번에 얼마나 떴는지"를 모터 신호만으로 안다 → 작업 품질 모니터링 | **가능** (`load_kg`, `scoop_dross` 라벨) | 하 |
| B | **공정 단계 인식** | 관절 신호 창(1~2 s) → 단계(스윕·상승·운반·덤프…) | 실제 로봇 로그에서 공정 상태를 자동 분할 → 단계별 시간·에너지 분석 | **가능** (`phase` 라벨) | 하 |
| C | **전류 디지털 트윈 + 잔차 이상 감지** | q, qd, qdd, 부하 → 정상 전류 예측, 실측−예측 = 잔차 | 잔차가 커지면 충돌·끼임·마찰 증가·과부하의 전조 → 예지 보전의 기본 | 회귀 학습은 가능, 이상 검증엔 **고장 데이터 필요**(5.3) | 중 |
| D | **이상·고장 분류** | 신호 창 → 정상 / 마찰 증가 / 과부하 / 충돌 근접 … | 원인별 경보 | **고장 주입 기능 필요** | 중 |
| E | **사이클 성과 예측·최적화** | 레인·드로스 분포·설정 → 회수량·사이클 시간·에너지 | 레인 선택·속도·잠김 깊이 최적화 → v1.2.0 AI 경로 최적화로 연결 | 가능 (`cycles` 시트 + `meta`) — 많은 에피소드 필요 | 중~상 |
| F | **예지 보전 (열화 추세)** | 장기간 RMS 전류·에너지 추세 → 남은 수명 | 정비 시점 계획 | **열화 모델 필요** (시뮬레이터에 마모 진행 추가) | 상 |

**추천 순서:** A·B로 데이터·파이프라인 검증 → C(디지털 트윈) → 고장 주입 후 D → E(v1.2.0과 연결) → F.

### 5.2 단계별 과정 (데이터 → 모델 → 활용)

1. **문제·지표 정의**
   - 과제마다 예측 대상, 쓰는 순간(실시간·사후), 성공 지표를 정한다.
   - 예: A는 MAE < 0.5 kg, B는 macro-F1 > 0.9, C는 잔차 기반 이상 AUROC > 0.95, 경보까지 걸린 시간.
2. **데이터 수집 계획 (시나리오 매트릭스)**
   - 대형 로봇 4종 × 측면 구성(없음·모드 1·모드 2) × 드로스 시드 1~N × 발생률(0·30·60) × 스윕 속도 × 잠김 깊이 × (고장 종류·강도).
   - 한 에피소드 = 자동 연속 5~10분, 20 Hz.
   - **에피소드 ID**와 설정을 `meta`에 남긴다.
3. **라벨링**
   - 지금 자동으로 나오는 라벨: 단계·사이클·부하·스쿱 드로스·알람.
   - 고장 라벨(종류·강도·시작 시각)은 고장 주입 기능에서 함께 기록한다(5.3).
4. **데이터 품질 점검**
   - 샘플 간격이 균일한지, 결측·중복이 없는지, 단위를 확인한다.
   - 로봇별로 분리하고, 같은 시각의 대형·측면 행을 정렬한다.
5. **전처리·특성 만들기**
   - 정규화: 축별 정격전류·관절 한계로 나눈다(로봇 크기가 달라도 비교 가능).
   - 창 나누기: 1~2 s, 50% 겹침.
   - 창 특성: 평균·표준편차·RMS·피크·피크 간격·FFT 대역 에너지·축 간 상관, |τ·ω| 에너지, 단계 지속 시간.
   - 사이클 특성: `cycles` 시트(피크·RMS·에너지·시간·회수).
6. **분할 (누수 방지)**
   - 행 단위가 아니라 **에피소드·시드 단위**로 학습·검증·시험을 나눈다(같은 에피소드의 이웃 행이 양쪽에 들어가면 성능이 부풀려진다).
   - 일반화 확인: **로봇 모델 하나를 통째로 빼고** 시험한다(leave-one-robot-out).
7. **기준선(베이스라인)**
   - 규칙: 예) 전류 RMS 임계값, 단계는 TCP z·속도 규칙.
   - 고전 ML: 선형 회귀 → RandomForest·XGBoost/LightGBM(창 특성).
   - 기준선보다 나아야 딥러닝을 쓴다.
8. **딥러닝 (필요할 때)**
   - 1D-CNN·TCN·LSTM·작은 Transformer(원시 시계열 창)
   - 이상 감지는 오토인코더(재구성 오차)·Isolation Forest
   - 디지털 트윈은 MLP/GRU 회귀
9. **평가**
   - 분류: F1·혼동 행렬. 회귀: MAE·R². 이상: AUROC·PR-AUC·오경보율·**탐지 지연**.
   - 로봇·조건별로 나눠 본다.
10. **해석**
    - SHAP·특성 중요도로 "어느 축, 어느 신호가 판단에 쓰였나"를 본다.
    - 물리적으로 말이 되는지 확인한다(예: 부하 추정에 J2·J3 전류가 중요해야 정상).
11. **활용·배포**
    - 학습한 모델을 ONNX로 내보낸다.
    - 브라우저에서 `onnxruntime-web`으로 실시간 추론한다 → 오버레이에 "추정 드로스 kg·단계·이상 점수"를 표시(v1.2.0 후보, 무서버 원칙 유지).
12. **시뮬레이션 → 실제 (5.6)**
    - 실제 로봇 로그를 같은 열 형식으로 받아 보정·전이학습한다.

### 5.3 의미 있는 결과를 위해 추가하면 좋은 기능 (다음 버전 후보)

|---|---|---|
| **고장 주입 (Fault Injection)** | 축별 마찰 배수(마모), 백래시, 전류 센서 잡음·드리프트, 툴 끝 추가 부하, 관절 속도 제한(감속기 이상), 장애물 근접. 시작 시각·강도를 `fault_*` 열로 기록 | 과제 C·D·F의 정답 라벨이 생긴다 |

| **드로스 환경 다양화** | 드로스 크기·밀도·점성·욕면 높이 랜덤화 | 모델이 시뮬레이터 특정 값에 과적합하지 않게(도메인 랜덤화) |

### 5.4 바로 해 볼 첫 실험 (추천 레시피)
- **데이터 모으기**
  - KR 210 + 왼쪽 UR10e(모드 1) + 오른쪽 UR5e(모드 1), 20 Hz, 자동 연속 10분.
  - 드로스 시드 1~5로 다섯 번 기록·추출(파일 5개).
- **과제 A (부하 가상 센서)**
  - `robot == 'main'`에서 `phase`가 '스쿱 상승'~'덤프 높이로 하강'인 행을 쓴다.
  - 입력: `i2_A, i3_A, i5_A, q2_deg, q3_deg, q5_deg, qdd2_dps2, qdd3_dps2`. 출력: `load_kg`.
  - 모델: RandomForest. 시드 1~4로 학습, 5로 시험. MAE를 보고하고, 축별 중요도가 J2·J3 중심인지 확인한다.
- **과제 B (단계 인식)**
  - 1 s 창 특성(축별 평균·표준편차·RMS 속도·전류) → `phase`(창의 최빈값).
  - LightGBM, 시드 단위로 분할. 혼동 행렬에서 '스윕' vs '스쿱 하강'을 구분하는지 본다.
- **Python 예시 (요지)**

```python
import pandas as pd, glob
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import mean_absolute_error
dfs = []
for k, f in enumerate(sorted(glob.glob('robosim-telemetry-*.xlsx'))):
    d = pd.read_excel(f, sheet_name='data'); d['episode'] = k; dfs.append(d)
df = pd.concat(dfs)
m = df[(df.robot == 'main') & df.phase.isin(['스쿱 상승', '스쿱 뒤로 기울임', '드로스 박스로 이동', '덤프 높이로 하강'])]
X = m[['i2_A', 'i3_A', 'i5_A', 'q2_deg', 'q3_deg', 'q5_deg', 'qdd2_dps2', 'qdd3_dps2']]; y = m['load_kg']
tr, te = m.episode < m.episode.max(), m.episode == m.episode.max()
rf = RandomForestRegressor(n_estimators=300, random_state=0).fit(X[tr], y[tr])
print('MAE kg', mean_absolute_error(y[te], rf.predict(X[te])))
```

### 5.5 주의할 점
- **추정 전류의 한계:** 근사 동역학이라 절대값은 실제 로봇과 다르다. 패턴(단계·부하에 따른 변화)을 배우는 데는 쓸 수 있지만, 실측 임계값을 그대로 옮기면 안 된다.
- **시뮬레이터 편향:** 규칙 기반 경로라 동작이 매우 규칙적이다 → 모델이 너무 쉽게 맞힐 수 있다. 조건 다양화·잡음·고장 주입으로 어렵게 만든다.
- **데이터 누수:** 시간 순서·에피소드를 무시한 무작위 분할 금지.
- **클래스 불균형:** 짧은 단계(쏟기 1.2 s 등)는 적다 → 가중치·재표본.
- **샘플링:** 빠른 현상(충돌 직전)은 60 Hz로 기록한다(파일이 커지므로 필요한 에피소드만).

### 5.6 시뮬레이션 → 실제 로봇
- 열 이름·단위를 UR RTDE와 대응시켜 두었다(4장). 실제 UR10e에서 RTDE로 `actual_q·actual_qd·actual_current`를 125~500 Hz로 받으면 같은 형식으로 바꿀 수 있다.
- 순서
  1. 시뮬레이션으로 파이프라인·특성·모델 구조를 확정한다.
  2. 실제 로그 소량으로 전류 스케일·마찰 계수를 보정한다(정격·마찰 파라미터는 `meta`에 있음).
  3. 전이학습·미세조정을 한다.
  4. 실제 데이터로만 최종 평가한다.

## 8. 결정 사항 (2026-11-05)
1. 전류·토크는 근사 동역학 추정값으로 제공하고 화면·파일에 명시한다.
2. 시간 기준은 시뮬레이션 시간(결정적), 실제 시각은 참고 열.
3. 열 이름은 ASCII + UR RTDE 대응표, 설명은 한국어 시트.
4. 엑셀은 자체 작성기(의존성 추가 없음). 대용량은 다음 단계에서 CSV/Parquet.
5. 표시 설정(어떤 버튼을 켰는지)은 저장하지 않는다(세션 단위).
