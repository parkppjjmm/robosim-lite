## 1. 목표 / 비목표

### 1.1 목표
1. **이상·고장 상황을 시뮬레이터에서 만들고 라벨을 자동으로 붙인다.**
   - 운전 이상: 충돌 근접, 관절 한계 근접, 특이점 근접, 안전 게이트 차단, 간섭 대기 초과, 흘림.
   - 기계 고장: 고장 주입(마찰 증가, 백래시, 과부하, 센서 잡음·드리프트).
2. **몬테카를로 시나리오 생성기로 정상·이상 에피소드를 대량으로 만든다.**
   - Node에서 화면 없이, 실시간보다 빠르게, 시드로 재현 가능하게 만든다.
3. **상황 조건부 이상 경계(threshold)를 학습하고 고정 threshold와 비교한다** (Python, 오프라인).
   - 결과물 ①: 상황별 축별 정상 범위 표
   - 결과물 ②: 사람이 읽는 가이드라인 규칙
   - 결과물 ③: 위험 영역 지도
4. **학습한 경계를 앱에 다시 불러와 실시간 경보로 보여 준다** (`thresholds.json` → 그래프 밴드·경보).

### 1.2 연구 질문 (Research Questions)
| RQ | 질문 | 확인 방법 |
|---|---|---|
| RQ1 | 상황 조건부 threshold는 고정 threshold보다 이상을 **더 정확하고 더 빨리** 잡는가? | 같은 테스트 에피소드에서 검출률(오경보율 1% 고정), 경보 선행 시간, 시간당 오경보 수 비교 |
| RQ2 | 이상이 일어나기 쉬운 상황은 어떤 조건인가? (가이드라인) | 결정 트리 규칙, 변수 중요도(SHAP), 작업 공간 위험 지도 |
| RQ3 | 경계 근처 집중(적응) 샘플링은 순수 몬테카를로보다 같은 성능을 **더 적은 에피소드**로 얻는가? | 에피소드 수 대비 성능 곡선 비교 |
| RQ4 (선택) | 시뮬레이터에서 구한 경계가 실제 로봇 로그에서도 통하는가? (sim-to-real) | 실제 로봇 로그 확보 시 상대 경계로 검증 (7.4) |

### 1.3 비목표 (v2.0.0에서 하지 않음)
- 브라우저 안에서 신경망 학습·추론(ONNX 등) — 학습은 Python 오프라인. 앱은 결과 표(`thresholds.json`)만 읽는다.
- AI 경로 최적화(원래 v1.2.0 계획) — v3.0.0에서 한다(`../v3.0.0/PRD_v.3.0.0.md`).
- 정밀 동역학(재귀 뉴턴-오일러 + 실제 관성 파라미터) — 선택 항목(FR-52, P3).
- 실제 로봇 연결(RTDE 실시간 통신) — 실제 로그 **파일 가져오기**만 선택 항목으로 둔다(FR-53).
- 안전 게이트를 끄거나 우회하는 모드 — 운전 이상은 "게이트가 막은 순간과 그 직전 여유값"으로 기록한다(원칙 유지).

## 2. 용어와 라벨 원칙

### 2.1 이상(Anomaly)의 종류
| 분류 | 코드 | 정의 (라벨 기준) | 단계 |
|---|---|---|---|
| 운전 이상 | `OP_COLL_NEAR` | 로봇–장애물·설비·다른 로봇·자기 자신의 **정확한 최소 거리** < 근접 기준(기본 여유거리 + 30 mm) | 경고(near) |
| | `OP_BLOCK` | 안전 게이트가 이동을 막음(충돌·특이점·도달 불가 등, 위반 유형 함께 기록) | 이상 |
| | `OP_JLIM` | 어느 관절이 한계까지 남은 각도 < 5° (경고), < 1° (이상) | 경고 / 이상 |
| | `OP_SING` | 특이점 지표가 감지 기준의 1.5배 안(경고), 기준 안(이상) | 경고 / 이상 |
| | `OP_HOLD` | 로봇 간 간섭 대기가 10 s 초과(경고), 20 s 초과 = 기존 알람(이상) | 경고 / 이상 |
| | `OP_SPILL` | 스쿱에서 운반 중 드로스가 떨어짐(흘림, 셀 집계와 같은 기준) | 이상 |
| 기계 고장 | `FT_FRICTION` | 고장 주입: 축 마찰 증가(감속기 마모) | 고장 |
| | `FT_BACKLASH` | 고장 주입: 백래시(유격) | 고장 |
| | `FT_PAYLOAD` | 고장 주입: 툴 끝 예상 밖 부하(드로스 고착·툴 손상) | 고장 |
| 센서 이상 | `SN_NOISE` / `SN_DRIFT` / `SN_BIAS` | 고장 주입: 전류 센서 잡음 증가, 서서히 어긋남, 일정 오프셋 | 고장 |

- **정상(normal):** 위 어느 것에도 해당하지 않는 샘플.
- **근접(near-miss):** 경고 단계. 이상은 아니지만 이상 직전 상황이다. 경계 학습에 가장 중요한 데이터다.
- 고장은 주입된 시각부터 끝까지 라벨이 붙는다(강도와 함께). 운전 이상은 샘플마다 판정한다.

### 2.2 라벨 원칙 (순환 논리 방지)
- 이상 라벨은 **입력 신호(전류·토크 크기)로 정하지 않는다.** "전류 > X이면 이상"으로 라벨을 붙이고 그 데이터로 전류 threshold를 학습하면 X를 다시 찾을 뿐이다.
- 라벨은 **결과**로만 정한다.
  - 기하 판정: 거리·한계·특이점·게이트 차단
  - 작업 결과: 흘림·대기
  - 주입 사실: 고장 종류·강도·시각
- 고정 전류 threshold 경보(기존 방식)는 라벨이 아니라 **비교 기준(baseline) 열** `fixed_alarm`으로 따로 기록한다.

### 2.3 threshold의 두 종류
| 종류 | 정의 | 역할 |
|---|---|---|
| 고정 threshold | 축마다 상수 하나(예: 정격 전류의 90%) | 비교 기준. 현재 산업 현장 방식 |
| **상황 조건부 threshold** | 상황 x(자세·속도·가속도·부하·단계)가 주어지면 축별 정상 범위 [하한(x), 상한(x)] | **이번 버전의 결과물.** 같은 8 A라도 팔을 뻗고 드로스를 떴을 때는 정상, 팔을 접은 빈 스쿱에서는 이상 |

```

 └──────────────┬───────────────────────┘
                │ ① 샘플러: 몬테카를로 / 라틴 하이퍼큐브 / 적응(경계 근처)
                ▼
 ┌─ 헤드리스 에피소드 실행기 (Node, js/cell-sim.js) ──────────────────────┐

                ▼

                │ ③ analysis/ (Python): Parquet 변환 → 특징 → 정상 밴드·분류·규칙
```

- **호환:** 고장 주입 꺼짐·경계 미적용 상태의 앱은 v1.1.2와 같게 동작한다.

## 4. 기능 요구사항 (FR-42 ~ FR-53)

우선순위: **P1 = v2.0.0 필수**, P2 = v2.0.0 권장, P3 = 선택(시간이 되면 / 이후 버전).

### FR-42 기록 확장 — 상황 변수 (P1)
기존 49열에 아래 열을 더한다(5장 스키마). 브라우저 기록·엑셀과 헤드리스 생성기가 **같은 열 정의**를 쓴다.
- **TCP 자세 전체:** `tcp_rx_deg`, `tcp_ry_deg`, `tcp_rz_deg`(roll·pitch·yaw, 기존 `rpyFromMatrix`)와 학습용 쿼터니언 `tcp_qw…qz`. ±180°에서 값이 튀는 문제 때문에 학습에는 쿼터니언이나 sin/cos를 쓴다.
- **팔 뻗음 지표:** `reach_ratio` = 베이스–손목 중심 거리 / 최대 도달거리 — 가이드라인을 사람이 읽기 쉽게 하는 대표 변수.
- **안전 여유 지표:**
  - `d_obs_mm`: 장애물·설비 정확 최소 거리. `minDistance`의 경계구 하한값이 아닌 정확값을 쓴다(CLAUDE.md 함정).
  - `d_self_mm`, `d_robot_mm`(다른 로봇)
  - `jlim_margin_deg`(6축 중 최소)와 `jlim_joint`
  - `sing_wrist_deg`, `sing_elbow_deg`, `sing_shoulder_mm`, `manipulability`
- **게이트·대기:** `gate_block`(이번 샘플 사이에 차단이 있었으면 1)과 `gate_violation`(유형), `hold_s`(간섭 대기 누적 초)
- **비교 기준:** `fixed_alarm`(고정 threshold 초과 축 수, 2.2)
- 계산 비용: 정확 거리 계산은 샘플 주기(기본 20 Hz)에만 한다(60 Hz 스텝마다 하지 않음).

### FR-43 이상 판정기 `js/anomaly.js` (P1)
- DOM에 의존하지 않는다. 브라우저와 Node에서 같이 쓴다.
- `AnomalyMonitor(config)`
  - `.update(sample)`: FR-42 열 + 셀 이벤트(흘림·대기·게이트 차단) + 고장 주입 상태를 받아 `{ label, codes[], severity, nearMiss }`를 낸다.
  - 판정 기준값(2.1 표)은 `ANOMALY_RULES` 상수 하나에 모은다. 학습 전후 비교를 위해 기준을 바꾸면 `meta`·`manifest`에 기록한다.
- 출력 열
  - `anomaly`: 0 = 정상, 1 = 근접(경고), 2 = 이상 또는 고장
  - `anomaly_codes`: 예 `OP_COLL_NEAR|FT_FRICTION`
  - `anomaly_severity`: 0~1 (가장 심한 항목 기준)
- **사후 라벨**(에피소드가 끝난 뒤 계산): `t_to_anomaly_s`(다음 이상까지 남은 시간, 없으면 빈칸)와 `pre_anomaly_Ns`(N초 안에 이상이 일어나면 1, N = 1·3·5). "곧 이상이 생길 상황" 예측의 정답이다.

### FR-44 고장 주입 `js/fault.js` (P1, 일부 P2)
- `FaultInjector(spec, seed)`: 에피소드에 고장 0~2개를 시간표로 넣는다.
- 각 고장의 시간 형태
  - `step`: 시작 시각부터 바로 최대 강도
  - `ramp`: 일정 시간에 걸쳐 0 → 최대(마모처럼 서서히)
  - `intermittent`: 켜짐·꺼짐 반복

| 고장 | 우선 | 파라미터 (범위) | 모델 (적용 위치) | 데이터에 나타나는 모습 |
|---|---|---|---|---|
| `friction` | P1 | 축, 쿨롱·점성 마찰 배수 1~4 | `telemetry.js` 마찰 항 × 배수 | 그 축 전류가 늘 높고 속도에 비례해 커짐 |
| `payload` | P1 | 추가 질량 0~(가반하중의 60%) kg | 계측 부하 + (물리 모드) 툴 끝 질량 | J2·J3 전류 증가, 자세에 따라 다름 |
| `sensor_noise` | P1 | 축, 잡음 표준편차 배수 2~10 | 전류 출력 잡음 | 신호가 지저분해짐 |
| `sensor_drift` | P1 | 축, 드리프트 속도 (정격 %/min) 0.5~5 | 전류 출력 + 누적 오프셋 | 서서히 어긋남 |
| `sensor_bias` | P1 | 축, 오프셋 (정격 %) ±2~15 | 전류 출력 + 상수 | 일정하게 어긋남 |
| `backlash` | P2 | 축, 유격 0.1~1.0° | 방향 전환 때 실제 각도가 지령보다 늦게 따라감(데드밴드) + 토크 순간 튐 | 방향 전환 때 전류 튐, 각도 지연 |
| `velocity_limit` | P2 | 축, 최대 속도 비율 0.3~0.8 | 궤적 시간 재조정(그 축이 느려짐) | 사이클 시간 증가, 다른 축과 동기 깨짐 |
| `encoder_offset` | P3 | 축, 0.2~2° | 실제 자세 ≠ 지령 자세(안전 게이트는 실제 자세로 검사) | 충돌 근접·흘림 증가 → 운전 이상으로 이어짐 |

- 데이터 열: `fault_active`(0/1), `fault_type`, `fault_joint`, `fault_level`(0~1, 현재 강도), `fault_id`(에피소드 안 번호)
- **브라우저 패널(P1):** "고장 주입" 섹션에서 고장 종류·축·강도·형태를 고르고 [주입] / [해제]를 누른다. 시연과 수동 데이터 수집용이다. 상태바에 "고장 주입 중" 배지를 띄워 정상 운전과 헷갈리지 않게 한다. 설정은 저장하지 않는다(세션 단위, 새로고침하면 해제).

### FR-45 시나리오 공간과 샘플러 `js/scenario.js` (P1, 적응 샘플링은 FR-50)
- `scenario-space.json`(`tools/` 아래)에 변수와 범위·분포를 정의한다.
- 샘플러가 에피소드 설정을 만든다. 같은 `master_seed`와 같은 번호면 항상 같은 설정이 나온다(재현성).

| 그룹 | 변수 | 기본 범위 |
|---|---|---|
| 셀 구성 | 대형 로봇(4종), 왼쪽·오른쪽 측면(없음 / 7종 × 모드 1·2) | 범주 |
| 드로스 | 초기 수(60~300), 발생률(0~60/분), 드로스 시드 | 균등 |
| 작업 설정 | 잠김 깊이(20~75 mm), 스윕 속도(30~250 mm/s) | 균등 |
| 자세 섭동 | 레인 목표점 오프셋(±60 mm), 덤프 위치 오프셋(±80 mm), 툴 기울기 오프셋(±5°) | 균등 |
| 외란 (P2) | 포트 주변 가상 외란 물체 0~2개(위치·크기 무작위, 셀 경계 안) | 균등 |
| 고장 | 없음(확률 0.5) / FR-44 종류·축·강도·형태·시작 시각 | 범주 + 균등 |
| 길이 | 에피소드 시뮬레이션 시간 120~300 s | 고정 또는 균등 |

- 샘플링 방법: `mc`(순수 몬테카를로, 기본), `lhs`(라틴 하이퍼큐브, 공간을 고르게), `adaptive`(FR-50).
- 셀이 불가능한 조합(예: 측면 박스 덤프 자세 없음)은 샘플러가 걸러 내고 `rejected` 수를 기록한다.

### FR-46 헤드리스 에피소드 실행기 `js/cell-sim.js` (P1)
- `tests/cell-robots.mjs`의 `simulate()` 루프를 공통 모듈로 옮긴다. 순서는 v1.1.2와 같다: 측면 로봇 → 대형 로봇 안전 게이트(다른 로봇 포함) → 물리, 60 Hz.
- 그 위에 고장 주입 → 계측 → 이상 판정 → 기록을 붙인다.
- `runEpisode(config, { RAPIER, onSample, hz }) → { summary, rows, events }`
  - DOM 의존 없음.
  - 비동기 계획 중에는 `await setImmediate`로 양보한다(CLAUDE.md 함정: 양보하지 않으면 교착처럼 보인다).
- 회귀 기준: 고장 없음·섭동 0 설정에서 `tests/cell-robots.mjs`의 기존 결과(안전 위반 0, 회수량 범위)와 같아야 한다. `cell-robots.mjs`는 이 모듈을 쓰도록 바꾼다.
- `main.js`(브라우저) 루프는 이번 버전에서 바꾸지 않는다. 다만 이상 판정·고장 주입 호출은 같은 모듈 함수를 쓴다.
- 목표 속도: 대형 + 측면 2대 기준 **실시간 대비 5배 이상**. v1.1.2 측정에서 60 s 시뮬레이션의 물리 합계는 약 2.5 s였다. 계획 시간을 포함한 실제 배속은 1단계에서 잰다.

### FR-47 일괄 데이터 생성기 `tools/generate.mjs` (P1)
- 실행 예:
  ```
  node tools/generate.mjs --space tools/scenario-space.json --n 200 --seed 42 --method lhs --hz 20 --workers 4 --out out/run-001
  ```
  - `--workers`: 자식 프로세스로 병렬 실행
  - `--resume`: 끊긴 지점부터 이어서
  - `--dry`: 설정만 만들고 실행하지 않음
- 출력 (`out/`은 git에 넣지 않음)
  - `manifest.json`: 앱 버전, git 커밋, 스키마 버전, 시나리오 공간, 판정 기준(`ANOMALY_RULES`), 생성 시각·소요 시간
  - `episodes.csv`: 에피소드당 1행. 설정 전체 + 요약(사이클 수, 회수, 흘림, 이상 횟수·종류별 시간, 고장)
  - `samples/ep-00001.csv.gz`: 샘플 행, 5장 스키마
  - `events.csv`: 단계·알람·게이트 차단·고장 시작/끝
- 형식: Node에는 Parquet 라이브러리가 없다(의존성 추가 금지 원칙). 그래서 **CSV(gzip)** 로 쓰고, Python `analysis/to_parquet.py`가 Parquet으로 바꾼다.
- 진행 표시: 에피소드 i/N, 남은 시간 추정, 실패(예외) 에피소드는 `errors.csv`에 남기고 계속 진행한다.

### FR-48 Python 분석 파이프라인 `analysis/` (P1)
| 파일 | 역할 |
|---|---|
| `requirements.txt` | numpy, pandas, pyarrow, scikit-learn, lightgbm, matplotlib, shap(선택) |

| `band_model.py` | **상황 조건부 정상 밴드:** 정상 샘플로 축별 전류(토크) 분위수 회귀 q=0.005·0.995(LightGBM quantile). 검증 세트로 conformal 보정해 목표 오경보율을 맞춘다 |

| `export_thresholds.py` | 앱용 `thresholds.json` 만들기(FR-49 형식) |

- Python 가상환경은 `analysis/.venv`(git 제외)에 만든다. 전역 설치는 하지 않는다.

### FR-49 학습 결과를 앱에 적용 (P1)
- **`thresholds.json` 형식 v1** (JS에서 바로 계산할 수 있게 표와 규칙으로)
  ```json
  {
    "schema": "robosim-thresholds/1",
    "created": "…",
    "source": { "run": "out/run-001", "episodes": 200, "app": "2.0.0" },
    "signal": "current_A",
    "bins": {
      "phase": ["sweep", "lift", "carry", "dump", "return", "idle", "other"],
      "reach_ratio": [0, 0.5, 0.7, 0.85, 1.01],
      "load_kg": [0, 5, 15, 40, 1000],
      "qd_abs_dps": [0, 5, 30, 1000]
    },
    "robots": {
      "<robotId>": {
        "band": [
          { "key": [phaseIdx, reachIdx, loadIdx, speedIdx], "lo": [6 values], "hi": [6 values], "n": 1234 }
        ],
        "fallback": { "lo": [6 values], "hi": [6 values] }
      }
    },
    "rules": [
      { "text": "팔 뻗음 > 0.85이고 부하 > 15 kg이면 J2 전류 상한 = 정격의 62%", "when": { "...": "..." }, "risk": 0.31 }
    ],
    "fixed": { "pct": 90 }
  }
  ```
  - 밴드는 구간표(단계 × 팔 뻗음 × 부하 × 속도)마다 축별 상·하한을 둔다. 회귀 모델을 구간 중앙값으로 요약해 만든다.
  - 표본이 적은 칸은 `fallback`을 쓴다.
- **앱 표시**
  - 계측 패널에 `[경계 불러오기]`(파일 선택)를 추가한다. 불러오면 그래프 전류 칸에 정상 밴드(반투명 띠)를 그린다.
  - 밴드를 벗어나면 오버레이 칸이 보라색이 되고 "조건부 경계 이탈 J2" 경보를 낸다. 경보만 하고 로봇을 정지시키지 않는다. 연구용 표시다.
  - 비교 표시: 같은 화면에서 고정 threshold 경보와 조건부 경보 횟수를 센다.
- 불러온 경계는 저장하지 않는다(세션 단위). 형식이 맞지 않으면 이유를 알린다.

## 7. 실험 설계

### 7.1 데이터셋 구성 (첫 실험)
- 1차: `lhs` 200 에피소드. 고장 없음 50%, 고장 50%(종류 고르게).
- 분할: 에피소드 단위로 학습 60% / 검증 20% / 시험 20%.
  - 대형 로봇 1종(예: SRA166)은 시험 전용으로 따로 둔다. 처음 보는 로봇에서도 통하는지(일반화) 본다.
- 무작위 행 단위 분할은 금지다. 같은 에피소드의 이웃 샘플이 학습·시험에 나뉘면 성능이 부풀려진다(데이터 누수).

### 7.2 비교 대상 (baseline)
1. 고정 threshold: 정격 대비 70·80·90%
2. 단계별 고정 threshold: 단계마다 정상 데이터의 99.5 분위수
3. **제안:** 상황 조건부 밴드(분위수 회귀 + conformal)
4. 참고: 위험 분류기(N초 안 이상 예측)

### 7.3 평가 지표
| 지표 | 뜻 |
|---|---|
| 검출률 @ 오경보율 1% | 오경보를 1%로 맞췄을 때 이상(고장) 구간을 잡은 비율 |
| AUROC / AUPRC | 임계값 전체에서의 분리 성능 (이상이 드물어 AUPRC를 함께 본다) |
| 경보 선행 시간 | 운전 이상(`OP_*`) 발생 몇 초 전에 경보했는가 (중앙값) |
| 고장 검출 지연 | 고장 주입 시작 → 첫 경보까지 시간 (강도별) |
| 시간당 오경보 | 정상 운전 1시간당 경보 수 |
| 샘플 효율 (RQ3) | 같은 성능에 필요한 에피소드 수 (적응 vs 순수 몬테카를로) |

### 7.4 실제 로봇 검증 (RQ4, 선택)
- 실제 로그(정상 운전만이라도)가 있으면 오경보율을 검증할 수 있다. 고장 기록이 있으면 검출률도 검증할 수 있다.
- 전이 방법: 절대 전류가 아니라 "정상 예측 대비 비율"로 경계를 정의한다. 또는 실제 정상 로그 일부로 밴드를 다시 보정한다(conformal 재보정).
