### 1.1 기준선 측정 (2026-11-05, `node tools/baseline.mjs` → `results/2026-11-05/1541_baseline_alone+mode1+mode2/report.md`)
조건: 600 s, 작업 영역 드로스 160개, 시드 11·12·13 평균, 추가 발생 없음, 회수율 = 셀 합계 ÷ 작업 영역 초기(개수, 괄호 = 질량), 36회, 6병렬 655 s.

| 대형 로봇 | 단독 | 3대 모드 1 (좌 UR10e · 우 IRB 1200) | 3대 모드 2 (좌·우 UR10e 밀기) |
|---|---|---|---|
| IRB 6700 | **61.1%** (59.8%) | **7.9%** ⚠ 대형 계획 실패 3/3 | **15.6%** |
| KR 210 | **61.3%** (61.0%) | **37.1%** | **53.3%** |
| R-2000iC/165F | **59.8%** | **36.9%** | **55.8%** |
| SRA166 | **62.5%** | **37.1%** | **57.1%** |

- **어떤 구성도 10분 80%에 도달하지 못한다(36회 중 0회).** 가장 좋은 것은 대형 단독(약 60~62%)이다.
- **측면 로봇을 붙이면 오히려 낮아진다.**
  - 모드 1: 대형 레인이 가운데(|y| ≤ 230)로 줄어 대형 회수가 98 → 46개가 된다. 측면 로봇은 10분 동안 17회 작업해 8개·5개만 회수하고(**헛질이 대부분**), 흘림은 약 12개다.
  - 모드 2: 측면 밀기 4~11회 뒤 "밀어 줄 드로스 없음"으로 쉬고, 대형은 잠금 대기 때문에 사이클이 줄어든다.
- **IRB 6700 + 측면 로봇(모드 1)은 대형이 덤프 자세를 찾지 못해 작업하지 못한다**: `S:1-7`(링크 1과 툴) 자기 충돌, 통로 규칙 경로. v1.1.1부터 있던 한계이며 이번 측정에서 발견했다(REVIEW 후보).
- 따라서 AI가 개선할 지점은 다음과 같다. ① 헛질을 줄이는 스트로크 선택(방향·위치) ② 벽 띠·모서리 회수 ③ 측면 로봇과의 협업(구역·시간) ④ 흘림 감소.

### 1.2 첫 결과 — 진화 탐색(Trial & Error, L1) (2026-11-05, `node tools/train.mjs`, `results/2026-11-05/*_cem_*/report.md`)
- 방법: 대형 로봇이 쉴 때마다 스트로크 후보 32개 × 4세대를 시도(지금 드로스를 복사한 물리 월드에서 한 사이클씩)하고 점수가 가장 높은 것만 실행.
  - 첫 세대에 규칙 레인을 넣고 절반은 그 근처, 절반은 전체 무작위로 둔다.
  - 점수 규칙: 회수 +10, 벽 띠 +5, 헛질 −20, 흘림 −5, 1 s −0.2, 계획 불가 −10.
  - Worker 14개로 10분 과제 1회에 약 3.5분 걸린다.

| 조건 (10분) | 학습(진화 탐색, 최선만 채택) | 규칙 경로 | 차이 | 헛질 |
|---|---|---|---|---|
| KR 210 단독, 시드 11 | **75.0%** | 61.9% | +13.1%p | 1 |
| KR 210 단독, 시드 12 | **75.6%** | 56.9% | +18.7%p | 0 |
| KR 210 + 좌 UR10e·우 IRB 1200 (모드 1), 시드 11 | **52.5%** | 38.8% | +13.7%p | 0 |

- 세 조건 모두 규칙 경로보다 13~19%p 높다. 아직 80%에는 못 미친다(최고 75.6%).
- **J6·방향 가설 확인:**
  - 초반(드로스가 많을 때)에는 규칙 레인이 최선으로 뽑힌다.
  - 드로스가 줄어든 중반부터는 대각선 방향(120~230°) + 스윕 중 열린 면 회전(예: −47° → +46°) + 약간 뒤로 기울임이 규칙 레인보다 점수가 크게 높다(예: 91점 vs 8점).
- 한계: 이 방식은 매 결정마다 시뮬레이터로 시도하는 **탐색**이라 현장에서 그대로 쓸 수 없다. 그래서 PPO 정책(관측 → 바로 스트로크)이 필요하다(6단계).

### 1.3 PPO 강화학습 첫 결과 (2026-11-05, `results/2026-11-05/1814_ppo-train_kr210-run1/`)
**학습 설정**
- 환경: KR 210 단독(StrokeEnv), 에피소드마다 다른 드로스 시드

- **다음 개선안**

  - ② 측면 로봇이 있는 셀·구역 제약을 학습 환경에 넣는다.
  - ③ 학습량을 늘리고, 모집단 학습(PBT, PRD 4.5)으로 시드 편차를 줄인다.

### 1.4 [A] 단계 — 측면 로봇 밀어 주기·대형 쓸기 방향 (2026-11-06, 사용자 제안)
- **사용자 제안**
  - ① 측면 로봇은 회수하지 않고 가운데로 밀어 주기만 하고, 대형 로봇만 회수한다.
  - ② 스쿱 열린 면이 로봇 반대(스나우트)를 보게 쓸어 스나우트 앞까지 회수하고, 들고 오는 동작까지 최적화한다.
- **구현 (규칙 경로, 학습 전)**
  - 측면 **모드 3 '타이밍 밀기'**: 대형이 포트 밖에 있고, 돌아오기 전(etaS)에 밀기 전체 + 1.5 s를 끝낼 수 있을 때만 민다.
    - 처음 설계한 구역 분리 동시 작업은 30 mm 간격 교착으로 폐기했다.
  - 대형 쓸기 방향 `task.mainRule.laneDir = robot | snout | alternate`.
    - snout은 들어 올린 뒤 450 mm 물러나 30°/s로 180° 돌린 뒤 운반한다.
    - 측면 로봇이 없는 셀에서만 적용한다.
  - 물리 엔진 수정: 쿼터니언 부호 뒤집힘(한 스텝 360° 회전) → `continuousRot`.

## 4. 행동 방식 — 두 가지 개념

> 두 방식 모두 **AI가 J1~J6 관절을 직접 움직인다.** 차이는 "무엇을 할지 정하는 판단"까지 같은 AI 하나가 하느냐(A), 판단과 동작을 나누느냐(B)다.

### 4.1 공통 요소
- **관측:** 드로스 점유 격자(상부 카메라), AI 로봇의 관절각·관절 속도·툴 위치·자세, 스쿱 위 드로스 추정량, 다른 로봇의 위치(캡슐), 남은 시간, 현재 회수율
- **안전 필터(8장):** AI가 낸 관절 움직임은 실행 전에 항상 검사한다. 위험하면 줄이거나 멈춘다. 시뮬레이터와 현장에 **같은 코드**를 쓴다.
- **시작은 모방:** 기존 규칙 경로(와 변형)를 따라 하게 먼저 가르친 뒤 강화학습으로 더 좋게 만든다(완전 무작위 시작 안 함).

### 4.2 개념 A — 순수 관절 직접 (End-to-End)
**쉬운 설명**
> AI 하나가 0.05초마다 "J1 +0.3°, J2 −0.1°, J3 +0.5°, …" 여섯 숫자를 낸다. 그것이 전부다.
> 자동차로 치면 **핸들과 페달만 주고 "목적지는 알아서 찾아가라"** 는 방식이다.

- AI는 다가가기 → 담그기 → 쓸기 → 들기 → 박스로 옮기기 → 쏟기의 **전 과정을 스스로 발견**해야 한다.
- 점수(보상)는 주로 드로스가 박스에 들어갈 때 나온다. 한 사이클(약 30 s)은 결정 600번인데 점수는 끝에 가서야 나온다(**늦은 보상**). 그래서 어느 결정이 좋았는지 가려내기 어렵다.

**기술 사양 (문서화, 실험은 P3)**
| 항목 | 내용 |
|---|---|
| 행동 | Δq ∈ ℝ⁶ (관절 속도 지령), 20 Hz, 관절 최대 속도 비율로 정규화 |
| 관측 | 4.1 공통 + 직전 행동 |
| 보상 | 박스 회수(+), 흘림(−), 안전 필터 개입(−), 시간(−), 관절 가속도 크기(−, 떨림 방지). 보상 쪼개기(스쿱 담김 증가 +)를 더할 수 있으나 그만큼 사람의 설계가 들어감 |
| 알고리즘 | 모방(BC) → PPO 또는 SAC |
| 예상 학습량 | 수천만 스텝 이상 (물리 시뮬레이터 속도로 수주~수개월 추정, 1단계 측정 후 재추정) |

**장점:** 사람이 생각하지 못한 동작을 찾을 가능성이 가장 크다. 구조가 단순하다.
**단점:** 학습이 매우 오래 걸리고 불안정하다. 떨림 같은 이상 동작이 생기기 쉽다. 판단 이유를 설명하기 어렵다. 현장에 "전부 아니면 전무"로 적용해야 한다.
**v3.0.0에서의 위치:** 인터페이스(같은 관측·안전 필터·환경)를 B와 공유하게 만들어 두고, B가 목표에 도달한 뒤 **같은 조건 비교 실험**(학습 곡선, 최종 회수율)으로 시험한다(FR-66, P3).

### 4.3 개념 B — 계층형 + 관절 직접 (본 방식)
**쉬운 설명**
> AI 둘이 역할을 나눈다.
> - **상위 AI = "작업 반장":** 드로스 지도를 보고 몇 초에 한 번 *"다음은 왼쪽 앞 모서리를, 벽에서 끌어내듯이"* 를 정한다.
> - **하위 AI = "숙련 작업자의 손":** 그 지시를 받아 0.05초마다 J1~J6를 **직접** 움직여 실제로 쓸어 담는다.
>
> 자동차로 치면 **내비게이션이 경로를 정하고, 운전자가 핸들·페달을 조작**하는 방식이다.

- 하위 AI는 "이 구역을 몇 초 안에 쓸어 담기" 같은 **짧은 과제**만 배운다. 쓸고 나면 스쿱에 담긴 양으로 점수가 바로 나오므로 학습이 빠르고 안정적이다.
- J6로 스쿱을 돌릴지, 손목을 기울일지, 팔꿈치를 어떻게 쓸지는 **모두 하위 AI가 학습**한다. 사람이 정하지 않는다.
- 이미 잘 되는 동작(들기·운반·쏟기)은 처음에는 기존 경로를 쓰고 나중에 학습으로 바꿀 수 있다.
- 현장 적용도 단계적으로 할 수 있다: 상위 AI만 먼저 적용(하위 = 기존 경로) → 검증 후 하위 AI까지 적용.

**스킬(상위 AI가 고르는 단위, 초안)**
| 스킬 | 파라미터 | 하위 실행 | v3.0.0 |
|---|---|---|---|
| `sweep_region` 구역 쓸어 담기 | 목표 칸(격자 구역), 진입 방향(8방향) | **하위 정책(Δq)** | P1 |
| `wall_pull` 벽에서 끌어내기 | 벽(앞·좌·우·스나우트), 구간 | **하위 정책(Δq)** | P1 |
| `corner_dig` 모서리 파내기 | 모서리 4곳 | **하위 정책(Δq)** | P2 |
| `carry_dump` 들어 올려 박스에 쏟기 | (자동: 스쿱 적재 시) | 기존 경로(`planSkimCycle` ④~⑨) → 이후 학습 대상 | P1(기존) |
| `wait_yield` 대기·양보 | 시간 | 기존 조정기 규칙 | P1(기존) |

**하위 정책 사양**
| 항목 | 내용 |
|---|---|
| 입력 | 공통 관측 + 스킬 종류(원-핫) + 목표 구역(로봇 좌표) + 스킬 경과 시간 |
| 출력 | Δq ∈ ℝ⁶ (J1~J6 관절 속도 지령), 20 Hz |
| 종료 | 스쿱 적재 ≥ 기준, 또는 시간 초과(기본 15 s), 또는 목표 구역 잔량 < 기준 |
| 보상 (촘촘) | 스쿱 위 드로스 질량 증가(+), 목표 구역 잔량 감소(+), 다른 구역 드로스 흩뜨림(−), 흘림(−), 안전 필터 개입(−), 관절 가속도·저크(−), 시간(−) |
| 학습 | ① 모방: 규칙 레인 + 사람이 만든 변형(벽 스윕·회전 스윕·모서리 대각선)을 관절 궤적으로 바꾼 시연 → BC ② 강화학습: PPO(병렬), 대리 모델로 사전 학습 후 물리 환경 미세 조정 |

**상위 정책 사양**
| 단계 | 방식 |
|---|---|
| B-상위-0 (P1) | 규칙: 잔량이 가장 큰 구역 + 벽 띠·모서리 우선 가중 + 다른 로봇 구역 회피 |
| B-상위-1 (P2) | 학습: 격자 → 스킬·구역 선택(가치 기반 또는 PPO), 보상 = 10분 회수율·도달 시간 |

**학습 순서:** B-1 하위 모방 → B-2 하위 강화학습 → B-3 상위 규칙으로 10분 과제 평가 → B-4 상위 학습 → B-5 전체 미세 조정.
모방(B-1)은 출발점일 뿐이다. 최종 정책은 **강화학습(B-2·B-4·B-5)으로 규칙 시연보다 나은 동작을 찾고, 4.5의 선택 과정을 통과한 것만** 쓴다.

### 4.5 다양한 자세에서 학습 → 최선의 모션만 채택 (D11) — FR-67

**쉬운 설명**
> 같은 일을 여러 자세·방법으로 수없이 해 보게 하고(탐색), 점수표로 줄을 세워 **가장 잘한 것만 남긴다**(선택).
> 남긴 것끼리 다시 더 해 보게 해 더 좋은 것을 찾는다. 마지막에 남은 1등 정책과 1등 모션들이 결과물이다.

**① 탐색을 넓게 (다양한 자세)**
| 무엇을 바꾸나 | 방법 |
|---|---|
| 시작 자세 | 매 에피소드 시작 관절값을 무작위로 한다. 같은 TCP라도 **다른 IK 해**(팔꿈치 위/아래, 손목 뒤집힘, J6 ±180°)에서 출발 |
| 스킬 목표 | 목표 구역·진입 방향·벽·모서리를 무작위로 |
| 드로스 상황 | 분포(고르게·벽 쏠림·모서리 쏠림·덩어리)·개수·시드를 무작위로 |
| 정책 탐색 | PPO 엔트로피 보너스, 행동 잡음. 학습 초반엔 크게, 후반엔 작게 |
| 여러 학습자 | 시드·하이퍼파라미터가 다른 정책 N개(기본 8)를 병렬로 학습(모집단) |

**② 최선만 남기기 (선택)**
| 단계 | 방법 | 남는 것 |
|---|---|---|
| 체크포인트 선택 | 학습 중 주기적으로(예: 50k 스텝마다) **고정 평가 세트**(시드·분포 고정, 처음 보는 자세 포함)에서 평가. 점수가 최고일 때만 저장 | 학습자마다 최고 체크포인트 1개 |
| 모집단 선택 (PBT 방식) | 일정 주기마다 하위 25% 학습자를 상위 25%의 가중치로 덮어쓰고 하이퍼파라미터를 조금 바꿔 계속 학습 | 점점 좋은 학습자만 남음 |
| 모션 라이브러리 | 학습·평가 중 나온 궤적을 (스킬, 구역, 드로스 상황 유형)별로 점수 순 **상위 K개(기본 5)** 만 보관. 점수 = 스킬 보상(회수량·흘림·시간·안전 개입·저크) | 상황별 최선 모션 모음 → **3D 재생 파일로 확인**, 자기 모방 학습 데이터로 재사용 |
| 최종 채택 | 평가 세트 + **학습에 안 쓴 시험 세트**에서 1등 정책을 고르고, 규칙 기준선과 비교해 더 나을 때만 채택 | `policy.json`·`policy.onnx` 1개 + 모션 라이브러리 + 비교 보고서 |

**점수 (선택 기준)**
- 10분 과제 기준. 1순위는 목표 회수율 도달 여부와 도달 시간, 2순위는 최종 회수율이다.
- 벌점: 흘림, 안전 필터 정지·개입, 관절 저크(떨림), 다른 로봇 대기 유발.
- 동점이면 에너지(추정)가 작은 쪽을 고른다.
- 선택 기준은 학습 기준(보상)과 따로 기록한다. "학습 점수만 높고 실제 과제는 못하는" 정책이 뽑히지 않게 하기 위해서다.

**③ (선택, P2) 실행 시 최선 후보 고르기 (best-of-K)**
- 매 스킬마다 정책이 후보 동작 K개를 뽑는다.
- 디지털 트윈(대리 모델)으로 몇 ms 안에 결과를 예측해 가장 좋은 후보만 실행한다.
- 현장에서는 대리 모델 정확도에 의존하므로, 시뮬레이터에서 효과를 확인한 뒤에만 쓴다.

**확인 방법:** 1등 정책의 10분 실행과 모션 라이브러리 상위 궤적을 에피소드 파일(`.rsim.json.gz`)로 저장해 앱에서 3D 재생한다(FR-63a).

## 5. 관측과 센서 — FR-56
- **센서 구성(설정):** 상부 카메라 1~2대
  - 기본 1대: 포트 중앙 위 높이 4 m, 수직 아래, 화각 70°
  - 2대: 좌·우 비스듬히, 가림 보완
  - 위치·자세·화각·해상도를 `task.sensors`로 바꿀 수 있다.
- **가상 카메라(시뮬레이터)**
  1. 드로스 입자를 카메라 시점에서 투영한다.
  2. 로봇 팔·툴 캡슐에 가려진 입자는 보이지 않는다(가림).
  3. 위치 잡음, 놓침·오검출 확률, 지연(프레임)을 넣는다.
  4. 결과를 **작업 영역 격자**(기본 50 mm 칸, 24 × 36)로 만든다. 칸마다 드로스 덮임 비율을 넣는다.
- **현장 인식(v3.1.0):** 실제 카메라 영상 → 드로스 분할 → 같은 격자. 열화상 또는 내열 RGB, 용융 아연 약 460 °C.
  - 시뮬레이터가 **같은 격자 형식**을 내므로 정책은 입력 차이 없이 그대로 쓴다.
- 카메라가 2대면 격자를 합친다(둘 중 하나라도 보이면 관측).
- 정책은 **센서 격자만** 본다. 시뮬레이터의 정답 입자 위치는 보상 계산에만 쓰고 관측에 넣지 않는다(현장과 같은 조건).

## 6. 학습 환경 — FR-55·60
- **헤드리스 셀 시뮬레이터(Node, DOM 비의존):** v1.1.2 셀 루프(측면 → 대형 안전 게이트 → 물리, 60 Hz)를 공통 모듈로 만든다.
  - AI 로봇 슬롯만 정책 제어로 바꾸고, 나머지는 기존 규칙·조정기로 움직인다.
  - v2.0.0의 `runEpisode` 설계와 이름·API를 맞춘다(12장).
- **환경 API:** `reset(task, seed) → obs`, `step(action) → {obs, reward, done, info}`
  - 하위 환경: 스킬 단위 에피소드
  - 상위 환경: 10분 과제
- **Python 다리:** Node 프로세스와 JSON 줄 단위 표준 입출력, gymnasium 호환, 작업자 N개 병렬, 비정상 종료 시 재시작
- **대리 모델:** 2D 근사 모델(스쿱 바닥이 지나간 면적·방향으로 입자를 옮김)로 하위 정책을 빠르게 사전 학습한다. 물리 환경에서 미세 조정·평가한다. 대리 모델과 물리의 차이를 보고한다.
- **도메인 무작위화(sim-to-real 대비):**
  - 드로스: 크기 분포·밀도·마찰·점착(입자 간 약한 결합)
  - 욕: 욕면 높이 ±20 mm, 점성 저항
  - 센서: 잡음·지연
  - 로봇: 관절 응답 지연·추종 오차, 툴 길이 오차 ±5 mm
- **재현성:** 같은 seed + 같은 행동이면 같은 결과가 나온다. 시간 제한 후처리는 반복 횟수 고정 모드로 돌린다.
- **속도:** 1단계에서 측정한다. 물리 60 s는 약 2.5 s(v1.1.2 Node 측정)이므로 하위 스킬 15 s는 1 s 안팎으로 예상한다.

## 8. 안전 필터 (Safety Shield) — FR-57
매 제어 주기(20 Hz) AI 출력 Δq를 아래 순서로 처리한다. 시뮬레이터·브라우저·현장이 **같은 로직**을 쓴다(현장은 같은 규칙을 Python으로 이식하고 교차 검증).
1. **관절 한계·속도·가속도 제한:** `robots.json` 한계 + 현장 설정(감속 비율). 잘라 낸다.
2. **다음 자세 예측 검사:** `evaluatePose` + 이동 구간 세분 검사(`sweepCheck`)를 한다. 자기 충돌, 설비(포트·스나우트·박스·받침대), 바닥, **다른 로봇 캡슐**, 특이점을 본다.
3. **위험하면:** Δq를 절반씩 줄여 다시 검사한다(최대 3회). 그래도 위험하면 **정지**하고 개입 횟수를 센다(보상 −).
4. **욕 아래 깊이 제한:** 플랜지·손목이 욕면 아래로 들어가지 않는다(툴만 잠김).
5. **기존 원칙 유지:** 모든 이동은 물리엔진보다 먼저 안전 검사를 통과한다.
- 현장에서는 이 필터 **바깥에 로봇 제어기 자체 안전 기능**(안전 구역·속도 제한·비상정지, ISO 10218)을 별도로 둔다.

  - v3.0.0이 먼저 진행하므로 `js/cell-sim.js`(`runEpisode`) API를 여기서 정하고, v2.0.0이 그대로 가져간다.
- 이후 합칠 지점
  - v2의 이상 판정(근접·흘림)을 v3 보상 벌점으로 쓰기
  - v2의 조건부 전류 경계를 v3 안전 필터의 추가 제약으로 쓰기
- 합칠 때는 새 버전 폴더에서 한다.
