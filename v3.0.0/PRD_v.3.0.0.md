## 2. 작업 정의 (Task Specification) — FR-54
```
task = {
  targetRatePct: 80,            // 목표 회수율 (설정, 10~100)
  zone: 'work',                 // 기준 영역: 'work'(스나우트 앞) — 확장 시 'custom' 사각형
  timeLimitS: 600,              // 제한 시간 (설정)
  aiRobot: { slot: 'main' | 'left' | 'right', robotId },   // AI가 조종하는 로봇
  cell: { main: robotId, left: {robotId, mode}, right: {robotId, mode} },  // 나머지는 기존 경로·모드
  dross: { count, seed, distribution, ratePerMin: 0 },     // 기본: 추가 발생 없음
  sensors: [{ pos, lookAt, fovDeg, res }],                 // 상부 카메라 1~2대
}
```
- **성공 판정:** `timeLimitS` 안에 `회수율 = (모든 박스 안 드로스 질량) ÷ (작업 영역 초기 드로스 질량) ≥ targetRatePct`. 질량과 개수를 함께 보고한다.
- **지표:**
  - 도달 시간(목표에 처음 도달한 시각)과 최종 회수율
  - AI 로봇 기여분, 로봇별 회수
  - 흘림, 안전 필터 개입 수, 계획 실패, 로봇 간 최소 거리
- **AI 로봇이 측면 로봇일 때**
  - 툴: 모드 1은 작은 스쿱, 모드 2는 밀대
  - 기존 조정 규칙(구역 경계, 모드 2 포트 점유 잠금, 간섭 시 양보)은 **제약으로 유지**한다. 구역 경계를 풀어 줄지는 설정으로 둔다(기본 유지).
- **AI 로봇이 대형일 때:** 측면 로봇은 기존 경로·모드로 계속 일한다. 대형 AI는 측면 로봇과의 간섭 규칙(통로·잠금)을 지킨다.

## 4. 행동 방식 — 두 가지 개념

> 두 방식 모두 **AI가 J1~J6 관절을 직접 움직인다.** 차이는 "무엇을 할지 정하는 판단"까지 같은 AI 하나가 하느냐(A), 판단과 동작을 나누느냐(B)다.

### 4.1 공통 요소
- **관측:** 드로스 점유 격자(상부 카메라), AI 로봇의 관절각·관절 속도·툴 위치·자세, 스쿱 위 드로스 추정량, 다른 로봇의 위치(캡슐), 남은 시간, 현재 회수율
- **안전 필터(8장):** AI가 낸 관절 움직임은 실행 전에 항상 검사한다. 위험하면 줄이거나 멈춘다. 시뮬레이터와 현장에 **같은 코드**를 쓴다.
- **시작은 모방:** 기존 규칙 경로(와 변형)를 따라 하게 먼저 가르친 뒤 강화학습으로 더 좋게 만든다(완전 무작위 시작 안 함).

### 4.2 개념 A — 순수 관절 직접 (End-to-End)
**쉬운 설명**
> AI 하나가 0.05초마다 "J1 +0.3°, J2 −0.1°, J3 +0.5°, …" 여섯 숫자를 낸다. 그것이 전부다.
> 자동차로 치면 **핸들과 페달만 주고 "목적지는 알아서 찾아가라"** 는 방식이다.

- AI는 다가가기 → 담그기 → 쓸기 → 들기 → 박스로 옮기기 → 쏟기의 **전 과정을 스스로 발견**해야 한다.
- 점수(보상)는 주로 드로스가 박스에 들어갈 때 나온다. 한 사이클(약 30 s)은 결정 600번인데 점수는 끝에 가서야 나온다(**늦은 보상**). 그래서 어느 결정이 좋았는지 가려내기 어렵다.

**기술 사양 (문서화, 실험은 P3)**
| 항목 | 내용 |
|---|---|
| 행동 | Δq ∈ ℝ⁶ (관절 속도 지령), 20 Hz, 관절 최대 속도 비율로 정규화 |
| 관측 | 4.1 공통 + 직전 행동 |
| 보상 | 박스 회수(+), 흘림(−), 안전 필터 개입(−), 시간(−), 관절 가속도 크기(−, 떨림 방지). 보상 쪼개기(스쿱 담김 증가 +)를 더할 수 있으나 그만큼 사람의 설계가 들어감 |
| 알고리즘 | 모방(BC) → PPO 또는 SAC |
| 예상 학습량 | 수천만 스텝 이상 (물리 시뮬레이터 속도로 수주~수개월 추정, 1단계 측정 후 재추정) |

**장점:** 사람이 생각하지 못한 동작을 찾을 가능성이 가장 크다. 구조가 단순하다.
**단점:** 학습이 매우 오래 걸리고 불안정하다. 떨림 같은 이상 동작이 생기기 쉽다. 판단 이유를 설명하기 어렵다. 현장에 "전부 아니면 전무"로 적용해야 한다.
**v3.0.0에서의 위치:** 인터페이스(같은 관측·안전 필터·환경)를 B와 공유하게 만들어 두고, B가 목표에 도달한 뒤 **같은 조건 비교 실험**(학습 곡선, 최종 회수율)으로 시험한다(FR-66, P3).

### 4.3 개념 B — 계층형 + 관절 직접 (본 방식)
**쉬운 설명**
> AI 둘이 역할을 나눈다.
> - **상위 AI = "작업 반장":** 드로스 지도를 보고 몇 초에 한 번 *"다음은 왼쪽 앞 모서리를, 벽에서 끌어내듯이"* 를 정한다.
> - **하위 AI = "숙련 작업자의 손":** 그 지시를 받아 0.05초마다 J1~J6를 **직접** 움직여 실제로 쓸어 담는다.
>
> 자동차로 치면 **내비게이션이 경로를 정하고, 운전자가 핸들·페달을 조작**하는 방식이다.

- 하위 AI는 "이 구역을 몇 초 안에 쓸어 담기" 같은 **짧은 과제**만 배운다. 쓸고 나면 스쿱에 담긴 양으로 점수가 바로 나오므로 학습이 빠르고 안정적이다.
- J6로 스쿱을 돌릴지, 손목을 기울일지, 팔꿈치를 어떻게 쓸지는 **모두 하위 AI가 학습**한다. 사람이 정하지 않는다.
- 이미 잘 되는 동작(들기·운반·쏟기)은 처음에는 기존 경로를 쓰고 나중에 학습으로 바꿀 수 있다.
- 현장 적용도 단계적으로 할 수 있다: 상위 AI만 먼저 적용(하위 = 기존 경로) → 검증 후 하위 AI까지 적용.

**스킬(상위 AI가 고르는 단위, 초안)**
| 스킬 | 파라미터 | 하위 실행 | v3.0.0 |
|---|---|---|---|
| `sweep_region` 구역 쓸어 담기 | 목표 칸(격자 구역), 진입 방향(8방향) | **하위 정책(Δq)** | P1 |
| `wall_pull` 벽에서 끌어내기 | 벽(앞·좌·우·스나우트), 구간 | **하위 정책(Δq)** | P1 |
| `corner_dig` 모서리 파내기 | 모서리 4곳 | **하위 정책(Δq)** | P2 |
| `carry_dump` 들어 올려 박스에 쏟기 | (자동: 스쿱 적재 시) | 기존 경로(`planSkimCycle` ④~⑨) → 이후 학습 대상 | P1(기존) |
| `wait_yield` 대기·양보 | 시간 | 기존 조정기 규칙 | P1(기존) |

**하위 정책 사양**
| 항목 | 내용 |
|---|---|
| 입력 | 공통 관측 + 스킬 종류(원-핫) + 목표 구역(로봇 좌표) + 스킬 경과 시간 |
| 출력 | Δq ∈ ℝ⁶ (J1~J6 관절 속도 지령), 20 Hz |
| 종료 | 스쿱 적재 ≥ 기준, 또는 시간 초과(기본 15 s), 또는 목표 구역 잔량 < 기준 |
| 보상 (촘촘) | 스쿱 위 드로스 질량 증가(+), 목표 구역 잔량 감소(+), 다른 구역 드로스 흩뜨림(−), 흘림(−), 안전 필터 개입(−), 관절 가속도·저크(−), 시간(−) |
| 학습 | ① 모방: 규칙 레인 + 사람이 만든 변형(벽 스윕·회전 스윕·모서리 대각선)을 관절 궤적으로 바꾼 시연 → BC ② 강화학습: PPO(병렬), 대리 모델로 사전 학습 후 물리 환경 미세 조정 |

**상위 정책 사양**
| 단계 | 방식 |
|---|---|
| B-상위-0 (P1) | 규칙: 잔량이 가장 큰 구역 + 벽 띠·모서리 우선 가중 + 다른 로봇 구역 회피 |
| B-상위-1 (P2) | 학습: 격자 → 스킬·구역 선택(가치 기반 또는 PPO), 보상 = 10분 회수율·도달 시간 |

**학습 순서:** B-1 하위 모방 → B-2 하위 강화학습 → B-3 상위 규칙으로 10분 과제 평가 → B-4 상위 학습 → B-5 전체 미세 조정.

### 4.4 A와 B 비교
| | A. 순수 관절 직접 | B. 계층형 + 관절 직접 |
|---|---|---|
| AI가 J1~J6를 직접 움직이나 | 예 | 예 (하위 AI) |
| 학습 난이도·시간 | 매우 높음 (수주~수개월 추정) | 중간 (수일~수주 추정) |
| 목표 80% 도달 가능성 | 불확실 | 높음 |
| 이상 동작(떨림) 위험 | 높음 | 낮음 |
| 현장 단계 적용 | 어려움 | 쉬움 (상위 → 하위) |
| 판단 설명 | 어려움 | 상위 결정 기록으로 설명 |
| 새로운 동작 발견 | 가능성 큼 | 하위 AI 범위 안에서 가능 |
| v3.0.0 | 문서·인터페이스, 비교 실험(P3) | **본 개발** |

## 5. 관측과 센서 — FR-56
- **센서 구성(설정):** 상부 카메라 1~2대
  - 기본 1대: 포트 중앙 위 높이 4 m, 수직 아래, 화각 70°
  - 2대: 좌·우 비스듬히, 가림 보완
  - 위치·자세·화각·해상도를 `task.sensors`로 바꿀 수 있다.
- **가상 카메라(시뮬레이터)**
  1. 드로스 입자를 카메라 시점에서 투영한다.
  2. 로봇 팔·툴 캡슐에 가려진 입자는 보이지 않는다(가림).
  3. 위치 잡음, 놓침·오검출 확률, 지연(프레임)을 넣는다.
  4. 결과를 **작업 영역 격자**(기본 50 mm 칸, 24 × 36)로 만든다. 칸마다 드로스 덮임 비율을 넣는다.
- **현장 인식(v3.1.0):** 실제 카메라 영상 → 드로스 분할 → 같은 격자. 열화상 또는 내열 RGB, 용융 아연 약 460 °C.
  - 시뮬레이터가 **같은 격자 형식**을 내므로 정책은 입력 차이 없이 그대로 쓴다.
- 카메라가 2대면 격자를 합친다(둘 중 하나라도 보이면 관측).
- 정책은 **센서 격자만** 본다. 시뮬레이터의 정답 입자 위치는 보상 계산에만 쓰고 관측에 넣지 않는다(현장과 같은 조건).

## 6. 학습 환경 — FR-55·60
- **헤드리스 셀 시뮬레이터(Node, DOM 비의존):** v1.1.2 셀 루프(측면 → 대형 안전 게이트 → 물리, 60 Hz)를 공통 모듈로 만든다.
  - AI 로봇 슬롯만 정책 제어로 바꾸고, 나머지는 기존 규칙·조정기로 움직인다.
  - v2.0.0의 `runEpisode` 설계와 이름·API를 맞춘다(12장).
- **환경 API:** `reset(task, seed) → obs`, `step(action) → {obs, reward, done, info}`
  - 하위 환경: 스킬 단위 에피소드
  - 상위 환경: 10분 과제
- **Python 다리:** Node 프로세스와 JSON 줄 단위 표준 입출력, gymnasium 호환, 작업자 N개 병렬, 비정상 종료 시 재시작
- **대리 모델:** 2D 근사 모델(스쿱 바닥이 지나간 면적·방향으로 입자를 옮김)로 하위 정책을 빠르게 사전 학습한다. 물리 환경에서 미세 조정·평가한다. 대리 모델과 물리의 차이를 보고한다.
- **도메인 무작위화(sim-to-real 대비):**
  - 드로스: 크기 분포·밀도·마찰·점착(입자 간 약한 결합)
  - 욕: 욕면 높이 ±20 mm, 점성 저항
  - 센서: 잡음·지연
  - 로봇: 관절 응답 지연·추종 오차, 툴 길이 오차 ±5 mm
- **재현성:** 같은 seed + 같은 행동이면 같은 결과가 나온다. 시간 제한 후처리는 반복 횟수 고정 모드로 돌린다.
- **속도:** 1단계에서 측정한다. 물리 60 s는 약 2.5 s(v1.1.2 Node 측정)이므로 하위 스킬 15 s는 1 s 안팎으로 예상한다.

## 8. 안전 필터 (Safety Shield) — FR-57
매 제어 주기(20 Hz) AI 출력 Δq를 아래 순서로 처리한다. 시뮬레이터·브라우저·현장이 **같은 로직**을 쓴다(현장은 같은 규칙을 Python으로 이식하고 교차 검증).
1. **관절 한계·속도·가속도 제한:** `robots.json` 한계 + 현장 설정(감속 비율). 잘라 낸다.
2. **다음 자세 예측 검사:** `evaluatePose` + 이동 구간 세분 검사(`sweepCheck`)를 한다. 자기 충돌, 설비(포트·스나우트·박스·받침대), 바닥, **다른 로봇 캡슐**, 특이점을 본다.
3. **위험하면:** Δq를 절반씩 줄여 다시 검사한다(최대 3회). 그래도 위험하면 **정지**하고 개입 횟수를 센다(보상 −).
4. **욕 아래 깊이 제한:** 플랜지·손목이 욕면 아래로 들어가지 않는다(툴만 잠김).
5. **기존 원칙 유지:** 모든 이동은 물리엔진보다 먼저 안전 검사를 통과한다.
- 현장에서는 이 필터 **바깥에 로봇 제어기 자체 안전 기능**(안전 구역·속도 제한·비상정지, ISO 10218)을 별도로 둔다.

회수율은 셀 합계 기준(D7, 사용자 확인)이다.

- 합칠 때는 새 버전 폴더에서 한다.
